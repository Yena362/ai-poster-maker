QR 포스터 메이커 — Firebase 사용 기록 연결

1. 기존 프로젝트 폴더를 먼저 복사해 백업하세요.
2. 이 ZIP을 풀고 아래 파일을 기존 index.html이 있는 프로젝트 폴더에 넣으세요.
   - index.html: 기존 파일을 교체
   - vercel.json: 기존 설정과 같음
   - package.json과 package-lock.json: 새 파일
   - api 폴더 전체: 폴더 안에 usage.js가 있어야 함
   - .gitignore: 비밀키와 로컬 설정의 실수 업로드 방지용
   기존 character.png는 그대로 두세요. ZIP에는 캐릭터 이미지가 포함되어 있지 않습니다.
   Firebase 비밀키 JSON 파일은 프로젝트 폴더에 넣지 마세요.

3. Vercel에 연결된 GitHub 저장소에 수정 파일들을 반영하세요.
   GitHub 웹사이트에서 저장소를 열어 Add file → Upload files로 올려도 됩니다.
   api 폴더를 통째로 드래그해서 api/usage.js 경로가 유지되도록 하세요.
   기존 index.html과 vercel.json은 교체하고 Commit changes로 저장하세요.
   VS Code의 Git을 쓰는 경우 Source Control에서 변경 파일을 확인하고 Commit → Sync Changes 하세요.
   어떤 방식이든 비밀키 JSON은 업로드 대상에서 제외하세요. 웹 업로드는 .gitignore가 막아주지 않습니다.

4. Vercel에서 자동 배포가 시작되는지 확인하세요.
   Settings → Build and Deployment의 Framework Preset은 Other를 사용합니다.
   이 프로젝트는 프런트엔드 빌드가 없으므로 별도 Build Command나 Output Directory 재정의가 필요 없습니다.
   배포 로그에 firebase-admin 설치와 /api/usage 함수 생성이 나타나야 합니다.
   자동 배포가 없으면 Git 연결과 배포 브랜치를 확인하세요.
   Git을 쓰지 않고 Vercel CLI로 배포하던 경우, 프로젝트 루트에서 기존 방식대로 vercel --prod로 배포하세요.

5. 이미 입력한 세 환경 변수가 Production에 있는지 확인하세요.
   FIREBASE_PROJECT_ID, FIREBASE_CLIENT_EMAIL, FIREBASE_PRIVATE_KEY
   키의 실제 줄바꿈과 문자열 \n 모두 처리하도록 구현했습니다.
   환경 변수만 바꾼 경우에는 그 뒤 새 배포가 필요합니다.

6. 배포 상태가 Ready가 되면 실제 운영 사이트를 열고 PNG 또는 PDF 저장을 눌러보세요.
   로컬 index.html 파일을 더블클릭하는 방식으로는 서버 기록 저장이 작동하지 않습니다.

7. Firebase 콘솔 → 데이터베이스 및 스토리지 → Firestore Database → 데이터
   usage_logs 컬렉션의 문서가 기록입니다. usage_limits는 하루 저장량 관리용입니다.
   createdAt: Firebase 서버 기록 시각 (화면 표시 시간대를 확인하세요)
   event: page_view = 페이지 열기, download_requested = 다운로드 시작 요청
   sessionId: 같은 탭의 이용 흐름을 묶는 임시 ID. 사람의 이름/Google 계정이 아닙니다.
   titles: 저장한 포스터 제목, 일괄 작업은 최대 10개
   theme: 색상 테마
   format: png / pdf / zip
   mode: single / batch
   posterCount: 해당 다운로드에 포함한 포스터 장수
   source: browser_reported (브라우저가 보고한 이벤트)

기록 범위 및 제한
- Google 로그인 기능은 추가하지 않았습니다. 사용자 실명·이메일은 알 수 없습니다.
- 새 탭이나 저장소 제한 설정에서는 새 세션 ID가 생길 수 있습니다. 세션 수는 사람 수가 아닙니다.
- 링크 원문, 업로드 이미지, 포스터 이미지, IP 주소는 Firestore에 저장하지 않습니다.
- 미리보기 변경은 기록하지 않습니다. 실제 파일 저장 완료를 확인하는 기능도 아닙니다.
- 클라이언트 보고 데이터이므로 누락/조작될 수 있어 결제·감사·정확한 생성 실적의 근거로 사용하면 안 됩니다.
- 페이지 열기와 다운로드 요청을 합쳐 한국 날짜 기준 하루 2,000개 저장 제한을 넣었습니다.
  한도 초과 또는 Firebase 장애 시 기록은 생략되고 포스터 기능은 계속 작동합니다.
- 이 한도는 저장 이벤트 제한이며 전체 요청/조회량이나 요금을 보장하는 제한은 아닙니다.
  무료 Spark를 유지하고 Firestore Usage에서 읽기·쓰기·저장량을 확인하세요.
  기록은 자동 삭제되지 않습니다. 불필요한 오래된 기록은 콘솔에서 삭제하세요.
- 서버 API는 쓰기 전용이며 전체 기록 조회 API나 공개 관리자 페이지는 없습니다.
  Firebase 콘솔에서 소유자 계정으로 확인하세요. Firestore 규칙은 프로덕션 모드로 유지하세요.
- 운영 도메인을 바꾸면 서버 환경 변수 USAGE_ALLOWED_HOSTS에 새 호스트를 추가하세요.
  예: posters.example.com (https:// 없이, 여러 개는 쉼표로 구분). 변경 후 재배포하세요.

기록이 안 보일 때
- Vercel Logs에서 Usage logging unavailable 메시지를 확인하세요.
- Firebase 프로젝트 ID/서비스 계정/비공개 키가 같은 프로젝트의 값인지 확인하세요.
- Firestore의 기본 데이터베이스 (default)가 생성되어 있는지 확인하세요.
- 브라우저 개발자 도구 → Network에서 /api/usage 응답을 확인하세요.
  404: api 폴더 배포 여부, 403: 도메인 설정, 429: 하루 기록 제한,
  503: 환경 변수/Firestore 생성 여부/서비스 계정 권한/무료 한도를 확인하세요.

검증 범위
- JavaScript 문법 및 서버 검증 로직은 로컬에서 확인했습니다.
- 실제 Firebase 비밀키를 받지 않았으므로 실계정 저장·운영 배포는 검증하지 않았습니다.
